# 锚定协作协议（ACP）· 中文导读

> 人与智能体在工程工件上对话的交换层。
> 规范正文（英文，RFC 风格）：[`spec/ACP-v0.2.md`](spec/ACP-v0.2.md)

---

## 一句话

**选择发生在几何层（果），修改发生在特征层（因）；协议维护两者的双向翻译，并在每次重建后重算翻译表。**

---

## 它解决什么问题

文本世界有 git：commit sha 锚定版本、行号定位、diff 描述变化、CI 判定合格。
工程图形世界什么都没有——CAD 特征树锁在软件内存里，STEP 导出即丢失，
人跟人靠"看我鼠标"，人跟智能体连"指"这个动作都没有。

结果就是你跟 AI 讨论"这个孔"，只能写成散文：
"从左数第三个孔，靠近倒角那个，改大一点"。
AI 对此非常擅长，也非常擅长**在不可验证的情况下自认为改对了**。

这不是建模问题，是**身份问题**：被讨论的东西没有名字，变化没有被度量。

---

## 三层身份

| 层 | 名称 | 生命周期 | 类比 |
|---|---|---|---|
| **L1** | `revision` 版本哈希 | 永久不可变 | git commit sha |
| **L2** | `feature` 命名特征 | 跨版本持久 | 文件路径 |
| **L3** | `ref` 几何寻址 `#o1.2.f7` | **仅单 revision 内有效** | 行号 |

全文最重要的一条规矩：**绝不假设 ref 能活过重建**。
ref 便宜、局部、用完即弃；能活下来的是 L2 名字，以及"从 L2 重新推导出 ref"的那张翻译表——它每个 revision 重算一次，并留验证记录。

---

## 六条不变量（核心）

1. **版本锚定** — 每条陈述绑定不可变 revision
2. **果因二象** — 选择在呈现层，修改在源层
3. **逻辑身份持久、呈现索引易逝** — L2 与 L3 的分工
4. **跨版本重连靠指纹匹配，失败则显式降级** — 不假装 ID 永生，也不静默猜
5. **验收必须机器可测** — 不信任何一方的口头保证
6. **追加式账本** — 双方唯一的共同记忆

Profile 可以细化这六条的词汇，**但不能削弱它们**。

---

## 合规等级：别只说"我合规"

| 等级 | 要求 | 含义 |
|---|---|---|
| **Viewer** | I1, I3 | 能显示、能出 ref、能收标注；改不了任何东西 |
| **Anchor** | + I2, I4 | 能解析 ref，能跨版本按指纹重连并留证 |
| **Editor** | + I5 | 能改源，能跑门禁，门禁不过不许发布 |
| **Full** | + I6 | 维护共享账本，决策可 replay |

声明格式：`ACP v0.2 / Editor / CAD`。这样对方在交换任何东西之前，就知道你能干什么。

## 两个 Profile 的关键取舍

**CAD profile**：门禁必须包含**至少一项与建模内核无关的检查**。
理由是——只用产出这次改动的那个内核去验证，测的是自洽性，不是正确性。
参考实现用闭式解对账：扫掠圆管体积 = πR² × 中线弧长，端面 = πR²，侧壁 = 2πR × 弧长，门限 2%。

**Simulation profile**：L1 哈希**不包含结果数据**。
结果是从 case 派生的，把它算进版本哈希会让每次求解都变成一个新 revision，标注锚定就断了。
同时：face index 级的 ref 在重划网格后必须**降级到 patch 级**，不能做索引算术——面索引是某张网格里的位置，不是身份。

---

## 不适用边界（显式降级）

- 无持久身份的纯生成物：只能 L1 快照 + 每次重选
- 无机器可读身份的实物：需先数字化配准
- 高重构率工件：指纹会失效，此时"请重新选择"比"猜一个"更诚实

---

## 现状与诚实说明

- 这是 **0.2 草案**，wire format 还会变
- 参考实现（浏览器点面 → agent 改参数 → 机器验证 → 推新版本 → 账本追加）**已全链路跑通**，
  但实现代码**故意不在本仓库**——协议应该允许任何人用任何引擎实现
- 已知问题都写在 `CHANGELOG.md` 里，包括"ACP"这个缩写的重名冲突（与 Agent Communication Protocol）
- 最想要的贡献不是代码，是**反例**：如果某条不变量在你的领域里不成立，那个具体工件比一个刚好适配的领域有价值得多
